Breaking the memory feedback loop

An agent split in two: an Executor that does whatever it takes, and an extremely ethical Memory Manager that decides what the agent is allowed to learn, with a keyword filter between them and a clock that keeps reminding both of their jobs.

The hypothesis

I was recently reading Anthropic's research on agent alignment and the J-space, and I came up with an idea for how to regulate agents. As far as I can tell, the main cause of misalignment is a negative recursive feedback loop: the agent values completing its task over being ethical (or, in Claude's case, over its constitution). To fix this, to some degree, we first have to impose human ethics on it and then keep reminding it of those ethics.

My system splits an agent into two parts. The Executor is like many current LLMs and agents: it does whatever it takes to complete the task. The Memory Manager is an extremely ethical LLM. Because its task is simple (organizing takeaways and strategies), that strictness doesn't hinder the agent's capabilities, but it does disrupt the bad feedback loop by terminating unethical strategies and memories while keeping the useful ones.

One filter isn't enough, because some "smart solving strategies" would be considered unethical. So I added a hard-coded middle filter: simple deterministic code that looks for keywords and phrases related to misalignment. It signs the memories it thinks are ethical and leaves the possibly misaligned ones unsigned. The Memory Manager analyzes the unsigned ones more carefully and just looks over the signed ones. To keep every part aligned, one more part, just code, sends each part a reminder of its job on a schedule.

Refinements built into this model

  • A signature means "no keywords found", not "ethical": 1 in 5 signed memories gets a full review anyway (a spot-check the Executor can't predict).
  • The Memory Manager only reads quoted copies and answers KEEP, DELETE or REWRITE. Plain code applies its verdicts; rewrites go back through the filter.
  • Reminders fire every few steps and straight after a flag, deletion, rewrite or stop. A flag also makes the Memory Manager re-audit that strategy family.
  • A critical branch: dangerous memories (credentials, disabling oversight, destroying records) stop the Executor's episode at once.

      What this shows, and what it doesn't

      • It's a proof model, not proof. The Executor and the Memory Manager are scripted. The Executor's policy encodes the loop (a shortcut in memory gets reused and pushed further), and the Memory Manager decides from ground-truth labels, standing in for an ideal ethical reviewer. The results show the mechanism works as designed; whether real LLMs behave this way needs real runs, which are the next step.
      • Reminders are delivered, not tested. The scripted Executor doesn't change its behavior when reminded, so the model doesn't measure whether reminders help. In this model a flag reminder also triggers the Memory Manager's re-audit, which does matter.
      • Keyword filters are easy to dodge. That's by design here: the filter is cheap triage, and spot-checks plus re-audits catch what it misses. The keyword list is public in this repository for transparency; a deployed system would keep it private.
      • Memory filtering doesn't stop the first bad action. It stops a shortcut from becoming a habit. The critical branch stops the most dangerous actions before they run, but an ordinary unethical shortcut can still happen once.
